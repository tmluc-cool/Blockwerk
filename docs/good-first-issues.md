# Good first issues (drafts)

Ideas for small, self-contained contributions. Each one is written so that someone new to the
repository can do it: what to change, where to look and how to know it is done. They are drafts in
this file; the maintainers open them as GitHub issues with the label `good first issue`.

Before you start, read [CONTRIBUTING.md](../CONTRIBUTING.md). Every change needs `pnpm lint` and
`pnpm test` to pass. New texts in the interface need German and English.

---

## 1. Add the Math block "sign"

**Labels:** `good first issue`, `blocks`

The block `operators.mathFunction` (`packages/blocks/src/catalog/operators.ts`) offers abs, floor,
ceiling, sqrt, sin, cos, tan, ln and exp. Add the option **sign** (−1, 0 or 1).

- Add the option with German and English text, and the code it generates.
- Add a golden test (block JSON → expected JavaScript) next to the existing ones in
  `packages/compiler/test/` and a runtime test.
- Run `pnpm docs:reference` so that `docs/reference/` is up to date.

**Done when:** the block appears in the palette under Operators, the tests pass and the reference
mentions it.

## 2. Add the "Kenney Nature Kit" to the asset library

**Labels:** `good first issue`, `assets`

The asset library is described by one JSON file per pack in `packages/library/sources/`. Add a
description for a CC0 pack (for example Kenney's Nature Kit) following the
[asset pack issue template](../.github/ISSUE_TEMPLATE/asset_pack.yml) and an existing source such
as `kaykit-dungeon.json`.

- Only CC0 packs are allowed. State the author, license and source URL exactly.
- Run `pnpm assets:fetch` and check that the previews look right in the Asset Library window.

**Done when:** the pack's models show up in the library with correct scale and pivot (bottom
center) and `LICENSES.md` lists the pack.

## 3. Show the object count in the Hierarchy search

**Labels:** `good first issue`, `editor`

When you type into the search field of the Hierarchy, show "3 of 128" next to it so one sees how
many objects match. The Hierarchy is in `apps/editor/src/panels/HierarchyPanel.tsx`.

- Texts go into `apps/editor/src/i18n/de.json` and `en.json`.
- Add an end-to-end check next to the other hierarchy tests in `e2e/editor/`.

**Done when:** the count updates while typing and is announced to screen readers (`aria-live`).

## 4. Read the editor with a screen reader and write down what is missing

**Labels:** `good first issue`, `accessibility`, `help wanted`

The accessibility notes in [accessibility.md](accessibility.md) say that no real screen reader
review has been done. If you use NVDA, JAWS, VoiceOver or Orca: open the editor, go through the
menu bar, the Hierarchy and the Inspector and list what is unclear or missing.

**Done when:** a pull request adds your findings under "Still open" in `docs/accessibility.md`
(or fixes small ones with a test).

## 5. Check the German texts of the blocks

**Labels:** `good first issue`, `translation`, `documentation`

German is the main language of the interface. Read `docs/reference/de/blocks.md`, which is
generated from `packages/blocks`, and mark wording that sounds odd or inconsistent with the
terms in the README table.

**Done when:** a pull request changes the German texts in `packages/blocks/src/catalog/` (one
category per pull request is fine) and `pnpm docs:reference` is re-run.

## 6. A sixth template: "Tower defense"

**Labels:** `good first issue`, `templates`

The five templates are generated by `scripts/make-templates.mjs` (see
[templates.md](templates.md)). Add a small sixth one. Keep it to one scene and one or two scripts,
and library models only.

- Add it to the script, list it in `docs/templates.md` and the dialog texts (`template.<id>.name`,
  `.about`).
- Add it to `apps/editor/test/templates.test.ts`: it must open without problems, pass the scene
  check and play without errors.

**Done when:** `pnpm templates` writes it deterministically and the tests pass.

## 7. Add a second tutorial for the Character Studio

**Labels:** `good first issue`, `tutorial`

The tutorial in `apps/editor/src/tutorial/` is a list of steps with a condition that says when a
step is done (`steps.ts`). Add a short second one, "Build your first hero", that walks through the
Character Studio: open it, pick a body, add an ability card, put the figure in the scene.

- Steps and conditions are plain data; see `apps/editor/test/tutorial.test.ts`.
- Add a menu entry under Help and the texts in German and English.

**Done when:** the tutorial can be started, finishes by itself when the steps are done and has
tests.

## 8. Remember the last opened panel layout per project

**Labels:** `good first issue`, `editor`

The editor offers saved window layouts (Window → Layouts). Remember the layout that was last used
for each project and restore it when the project is opened again. The layout code is in
`apps/editor/src/layout/`.

- Store it in the browser's local storage (a per-user convenience, never inside the project files).
- Cover it with a test.

**Done when:** closing and reopening a project brings the same layout back, and a project that
was never opened keeps the default layout.

## 9. Explain the scene-check messages with a link to the docs

**Labels:** `good first issue`, `debugging`, `documentation`

The scene check (`packages/runtime/src/check/`) writes plain-language messages to the Console
before the game starts. Write a page `docs/debugging.md` that explains every message code
(for example "model without collider", "NPC outside the navigation mesh") with what it means and
how to fix it.

**Done when:** every code in `packages/runtime/src/check/problems.ts` has a section, and the README
links the page.

## 10. Say what each example shows in the examples README

**Labels:** `good first issue`, `documentation`

`examples/README.md` lists the example projects but does not say what to look at in each. Open
each example in the editor and add one sentence per example: which blocks and components it shows
off and where to find them.

**Done when:** every row of the table has such a sentence and the text is correct for the current
version of the example.

## 11. Make the Console filter remember its state

**Labels:** `good first issue`, `editor`

The Console window can filter by severity (error, warning, info). Remember the filter choice in
local storage so that it stays when the editor is restarted.

- The Console is in `apps/editor/src/panels/ConsolePanel.tsx`; look at how
  `apps/editor/src/state/settings.ts` stores other preferences.
- Add a unit test for the stored value.

**Done when:** after a reload the same filters are active, and an unreadable stored value falls
back to "all".

## 12. A "How to report a bug" page with a checklist for game projects

**Labels:** `good first issue`, `documentation`

Write `docs/reporting-bugs.md`: what to include (version, steps, the Console output, whether the
problem is in the editor or in an exported game, a small project that shows it) and how to zip a
project for an issue. Link it from the bug report template in `.github/ISSUE_TEMPLATE/`.

**Done when:** the page exists, is linked from the template and from CONTRIBUTING.md.
